# 开发、变更与交付流程

本轮采用 Controlled：新建前后端共享 API/数据库契约，且保护历史资料。文档先于业务实现。

1. INTAKE / BASELINE：读根及模块 AGENTS，记录需求证据、目录与保护哈希。
2. PLAN / PRODUCT_UX_GATE：记录页面、用户路径、真实/合成内容和异常状态。
3. CONTRACT_FREEZE：冻结数据字段、查询/导入 API、指标和权限边界；剩余未知显式列出。
4. DISPATCH：任务票写目标、范围、责任人、依赖、验收和证据；按文件划分并行。
5. INTEGRATE：先迁移本地DuckDB，再导入样例；前端连接真实API；共享契约漂移由主代理协调。
6. QA / UX_REVIEW：独立验证持久化、预览无正式写入、对比/过滤/分页、空值与来源、桌面及窄屏。
7. FIX / RE_QA：P0/P1 必须修复并复验；P2 记录责任和是否阻断。重复同类失败先查根因。
8. FINAL_GATE / DELIVERY_DECISION：独立评审给出 PASS、PASS WITH FINDINGS、BLOCKED 或 FAIL，主代理结合证据决定交付。
9. RUN_RETROSPECTIVE / CLOSE：更新状态、启动方式、证据和下一步；总结代理分工与修复；不自动更新全局记忆或技能。

## 数据变更

新文件 → 记录来源/哈希 → 字段和数值校验 → 预览错误及样本 → 提交单事务 → 新版本可查询 → 重启仍存在。预览必须标明未入库；数据不满足规则不能“修成合理数字”。

## 数据库变更与恢复

评估迁移 → 测试库执行 → 备份 → 执行迁移 → readiness 和数据核对。不可逆变更单列；恢复先另建库验证，再决定切换，禁止自动删卷。

## 交接

项目状态与运行证据必须一致；交付说明包括已完成、本轮未开始、测试结果、风险、运行停止方法及待 IT/业务确认项。不要把本地验收写成生产就绪。
